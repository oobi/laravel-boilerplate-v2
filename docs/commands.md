# Custom Artisan commands

Commands the boilerplate itself adds (as opposed to Laravel/Livewire/Filament's
own built-ins). All boilerplate-provided commands are namespaced under `bp:`
so `php artisan list` groups them separately from framework/package commands —
update this doc whenever one is added, renamed, or removed.

| Command | Purpose |
|---|---|
| `bp:make-admin` | Interactively creates an admin user (first name/last name/email/password prompts via Laravel Prompts; `--first-name=`, `--last-name=` and `--email=` skip their prompts, the password is always prompted so it never lands in shell history). By default a **super admin**: the first account should be one, since only a super admin can grant super admin and untangle any role (an Administrator acts only on users and roles whose permissions it holds). Pass `--administrator` to put the user on the seeded **Administrator** role instead (everything a role can grant, without the master key), the right choice for every admin after the first; fails clearly if that role hasn't been seeded. Warns when creating a second super admin. Never a seeder, never hardcoded credentials. |
| `bp:make:panel` | Scaffolds a new admin page panel (a Show card and/or an Edit form section) under `app/Panels/Users/`. Prompts for the panel kind and, for Show panels, the region (main/sidebar). Reminds you to register it in `App\Support\Panels\AdminPanels`, or via `PanelRegistry::for(...)->add(...)` if it's an add-on. See `docs/architecture.md`. |
| `bp:setup` | Shapes a fresh clone into a supported app recipe (see `docs/config-recipes.md`): prompts for the recipe (Public SaaS / Invitation-only / Backoffice / Vanilla), or takes `--recipe=`, and writes the teams config (creation mode, invitation switches, `LOGIN_FALLBACK`, optional label relabelling) to `.env`. Vanilla hands off to `bp:remove-teams`; Backoffice asks whether to keep the tier (`--without-teams` drops it via `bp:remove-teams`, and a tier already removed is skipped) and hands off to `bp:make-login-only`. The teams recipes refuse to run once the tier is gone. Supports `--dry-run` and `--force` (keeps the tier unless `--without-teams`). |
| `bp:make-login-only` | Makes the app login-only, the structural half of the Backoffice recipe: a one-shot setup-time transform. Consumes the `public:start`/`public:end` markers (the `/` route becomes `LoginOnlyHomeController`, `Features::registration()` goes) and deletes the files only the public landing page and sign-up use (`MakeLoginOnlyCommand::PUBLIC_FILES`, their tests included), then checks the app still loads, putting everything back if not. Prints its plan and confirms first; running it again changes nothing. Supports `--dry-run` and `--force`. |
| `bp:roles:sync-implications` | The data fix after an implication map changes (`SystemPermission::implies()`, `TeamPermission::implies()`, or any registered `RoleScope::implications()`). A role's grants are `role_has_permissions` rows joining the role to `permissions` rows; roles are written closed over the map, so a row for "delete users" always comes with rows for "view users" and "access admin panel", and one for "manage team members" with one for "view team members". When a map gains an entry, roles written earlier are missing the new implied rows — this inserts exactly those rows (one per role per implied permission it lacks, following the chain, creating the `permissions` row first if the case is new) for every registered scope and touches nothing else: not a role whose scope has no `RoleScope` registered, and never a deletion — removing an implication needs no fix, the role keeps its now-ordinary grant. Idempotent, safe on every deploy; `--dry-run` prints each scope, role and the rows it would gain. |
| `bp:remove-teams` | Removes the teams tier and makes the boilerplate vanilla: a one-shot setup-time transform. Consumes the `teams:start`/`teams:end` markers to strip the tier's contributions from core files (replacing `User.php`'s block with its `teams:canonical:` line), checks the stripped app still loads (putting everything back if not), drops the path repository and runs `composer remove concise-dot-digital/teams`, then deletes `tests/Feature/Teams` and `packages/teams`. Destructive: prints its plan and confirms first; exits non-zero on any failure; supports `--dry-run` and `--force`. See `docs/teams-distribution.md`. |
