# Tables

## Row actions go in a menu, never as raw buttons
Every table's row actions are wrapped in `ActionGroup::make([...])` — the ⋮ menu (see `ListUsers`). Do not render row actions as inline buttons or links unless the user explicitly asks; the same goes for a hand-built daisyUI table, which must use a dropdown menu. A row of coloured buttons is noisy, wastes width, and is inconsistent with every other list.

## Entity names link to their view page, styled as links
The name/title cell of any listed entity is a link to its show page and reads as one (blue: `link link-hover`, as in `filament.tables.columns.user-column`). Use a ViewColumn (user-column, `teams::filament.tables.columns.team-column`) or an equivalent; never plain black text with an invisible `->url()`.

## A table's primary action lives in its toolbar
"Add …" / "Invite" for a table goes in the `<x-table-header>` `actions` slot, beside the search and filters — never in a row of its own above the table (a lone button row leaves a dead gap, see the team Members tab history) and, on a tabbed page, never in the shared page header. The one exception is a top-level list page whose page header *is* the table's header (Users, Teams), where "Add …" sits in the page header's actions. When the table is a shared child component, the action moves into the child and gates its own visibility. A table with no toolbar of its own, embedded in a section (the User page's Team memberships), puts its action in the section's header actions, in the heading row, never a row of its own.

## Users are listed with the user/avatar column
Wherever a table lists people (members, owners, authors, assignees), use `filament.tables.columns.user-column` (avatar, linked name with a muted "(you)" for the signed-in user, email). When the row isn't the user itself, pass the related `User` as the column's state (`ViewColumn::make('owner')`); the view accepts either, and shows a related user compact (small avatar and name, no email) so it doesn't compete with the row's own subject. Never a bare name/email `TextColumn`.

## Tables stack their rows on a phone; never scroll sideways
Every Filament table is ->stackedOnMobile(), set globally in AppServiceProvider's Table::configureUsing(); filament-table.css tightens the cards below `sm` (first cell unlabelled, label and value on one line, row menu and checkbox top right). A column's ->alignCenter() or ->alignEnd() applies to the desktop grid only: in the card every label and value starts at the same edge. Hide low-value columns (dates such as last login, created, sent; counts) below a tablet with ->visibleFrom('lg'): they stay sortable and on the show page. ->visibleFrom() hides a column in the stacked phone card too, so never use it on a column the phone needs. A column of several badges adds ->wrap() so they stack rather than widen the table; a custom cell view (user-column, team-column) wraps from `sm` itself, since Filament's rows don't. A secondary custom cell may also cap its width so the primary column keeps the room (the Users list's Teams cell), which then needs `wrap-anywhere` too: `whitespace-normal` only breaks at spaces, so a long unbroken name would overlap the next column. Clamp it (`line-clamp-2`, the full text in a `title`) so one long name can't make a tall row. A list of people whose other cells are self-describing (role badges, a status) adds ->extraAttributes(['class' => 'ui-stacked-compact']) so the badges sit under the name like a native list item (ListUsers, MembersTable); not for a table with unlabelled dates or bare numbers (a count that names itself, "2 teams", is fine). There an empty cell (a ->placeholder(), or a custom cell view marked data-cell-empty) is visually hidden but still read out, so a placeholder must only ever mean "none". Only a genuinely wide data grid opts out with ->stackedOnMobile(false) (theme-demo "wide"). Never use Split/Stack/Panel to make a table fit a phone: any layout component renders the table through Filament's layout renderer at every width and loses the desktop header cells. When a table does use layout components (row expansion), line its rows up with a Layout\Grid (fixed column spans), not a Split, which sizes each row's columns to their own content. Switch the Grid's columns by the table's width with a container breakpoint (`'@4xl' => 12`), not a screen one (`md`): beside the pinned sidebar a laptop's table is narrow. filament-table.css gives the rows of a table under 56rem the phone placement (checkbox and ⋮ top right). See theme-demo "maximalist".

## Tab panels holding a table go flush on their own
A `<x-tabs-nav>` panel whose content is just a table, or a toolbar (`<x-table-header>`) then a table, directly or inside one wrapper element (a Livewire component's root), drops its padding (tabs.css): the table loses its own border and the toolbar becomes a strip under the tabs. Don't pass `flush` for that, and don't add other elements beside the toolbar and table in such a panel, or it keeps the padding. The panel padding lives in tabs.css, not utility classes on the panel.

## A table's toolbar sits directly before the table
filament-table.css keeps Filament's own header hidden in a modal only when `<x-table-header>` (`.ui-toolbar`) is the table's immediate previous sibling. Wrap either one, or put another element between them, and a table in a modal or slide-over shows two search boxes. A modal table with no toolbar of ours (a TableSelect field) keeps Filament's search and filters.

## The toolbar folds its filters on a phone; filters count themselves
Below sm, <x-table-header> puts search and a "Filters" button on one row and folds its `filters` and `counts` slots into a panel (automatic, no prop; never hand-roll the button). Put only filters in those slots: anything there is hidden until opened; actions go in `actions`. The button's badge counts every control with `data-table-filter="{wire:model path}"` whose value isn't empty: table-filter-select, listbox, date-picker and trash-toggle set it, a hand-written filter control must too, with an empty "all" value (null, '' or []). A toolbar action may show just its icon on a phone with Filament's `->labeledFrom('sm')` only when the icon names the action on its own (user-plus for Add member); keep the label for a generic icon (plus, envelope) and always on a destructive action. Only a Filament action can do this; a Blade <x-button.*> in `actions` always shows its label. Filament's "Active filters" bar stays at every width. See docs/boilerplate/design-system.md, "The toolbar on a phone" (settled 2026-11-03).

## Bulk actions: one group, coloured by intent; selection needs nothing per table
Every Filament table's selection is handled centrally (filament/tables/selection-bar via a render hook in AppServiceProvider, filament-table.css, table-selection.js): the count names the rows from the model label, a selected row uses --ui-selected-bg (tokens.css; reuse it for anything else selectable, never grey), one selection per page, and below lg a bottom bar and sheet of solid buttons. Put a table's bulk actions in one BulkActionGroup (it names the bar's button; a loose BulkAction shows twice on a phone with Filament's native header). Colour each by intent: danger destructive, warning consequential but reversible, success restorative, otherwise the default primary; never gray (a solid grey button reads disabled). See docs/boilerplate/design-system.md, "Selection and bulk actions" (settled 2026-11-03).

## Long and wide tables stay usable by themselves; a hand-built table uses x-table-scroll
Every Filament table gets this centrally (filament-table.css, the filament/tables/scroll-rail render hook, table-scroll-rail.js), with nothing per table: from lg up the column header stays in view (below lg it scrolls away: Safari draws the scroll-driven animation badly while its toolbars move, wobbling the header and leaving rows undrawn, and a fits-or-not split made tables look inconsistent), a scroll rail and fades show while it overflows (replacing the native scrollbar, hidden on touch and off screen on a long table), the actions column is frozen, and from sm up pagination sticks unless the screen is under 500px tall. A table built from layout components has no header row or frozen column, and the column only freezes when the row actions are the last cell. Stacked rows on a phone have nothing stuck, by choice: they label themselves, and the Sort by strip stays unfrozen. Change it per table with classes, never by overriding .fi-*: ui-sticky-footer-phone, ui-no-sticky-footer-desktop, ui-no-sticky-header-desktop, ui-no-rail-arrows-phone/-desktop. A hand-built daisyUI table goes in <x-table-scroll>, never a bare overflow-x-auto wrapper. Its frozen column is opt-in (<th class="ui-table-actions">), and a tinted row sets --ui-row-bg on its <tr>. An <x-dropdown> in <x-table-scroll> is cut off on the last rows for now, even when the table fits (#21). Traps: sticking needs overflow-clip, not hidden, between the table and the page's scroller (<main> from lg up, the document below it, so nothing on the page should set html's scroll-padding-top: it also catches the sticky bar and focus there jumps the page). position: sticky can't do the header inside a sideways scroller, hence the scroll-driven animation; Livewire morphs would strip its range, which keepTableScrollStateThroughRenders carries over. Component state goes in closure variables, since Alpine writes undeclared keys to the shell's scope. Don't use scroll-padding for the frozen column (tabbing through row menus scrolls to the table's end). Playwright's --hide-scrollbars and its deviceScaleFactor hide real bugs here: check with scrollbars on and --force-device-scale-factor=1.1. See docs/boilerplate/design-system.md, "Long and wide tables" (settled 2026-11-05).
